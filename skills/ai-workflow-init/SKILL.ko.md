# AI Workflow Init

AI 에이전트가 프로젝트에서 매번 같은 방식으로 일하도록 하는 규칙 문서를 백지 상태에서 만든다. 인터뷰 → 생성 파일 목록 승인 → 기록 순서로 진행하며, 이미 있는 파일은 덮어쓰지 않는다.

> **이런 분께 추천**: AI 워크플로우를 처음 도입해보는 사람, 복잡한 설정 없이 최소한의 내용으로 구성하고 싶은 사람.
>
> **명시 호출 전용.** 사용자가 `/ai-workflow-init`을 호출할 때만 실행한다.
>
> **이 버전의 범위.** 큰 작업 워크플로우는 `feature-strategy` / `speckit` / 직접 입력한 스킬 / 없음, 이슈 트래커는 GitHub 이슈 / 없음(로컬 문서만) / 기타(사용자가 이름만 입력, 위임) 중에서 고른다. 스택은 프론트엔드/백엔드/풀스택 모두 가능하다. 이 범위를 넘는 즉흥 대응은 하지 않는다.

인터뷰 한 턴의 출력은 **질문과 추천 답 한 줄(`추천: …`)뿐**이다. 질문 1~5를 포함해 모든 질문 아래에 추천 답을 별도 줄로 둔다. "~로 기록하고 이어서 ~를 질문할게요", "빈 프로젝트라 건너뛸 파일이 없으니…" 같은 내부 단계 나레이션과 이전 답의 되풀이를 쓰지 않는다. 채팅 요약에서도 선택하지 않은 전략의 이름을 언급하지 않는다(남은 `{{슬롯}}`이 없다는 말만 한다).

질문은 항상 같은 모양으로 보여 준다: `### 질문 3/8 · 기술 스택` 제목 → 왜 묻는지 한 줄 → 선택지가 정해져 있으면 번호 목록(추천에 `← 추천` 표시) → `> 추천: 1. 프론트엔드 — 짧은 이유`. 질문 하나는 약 8줄 이내로 유지하고, 자유 서술 질문은 번호 목록 없이 제목·한 줄 설명·`> 추천:` 줄만 둔다.

모든 원본 자료는 이 스킬의 `references/`에 있다. **외부 템플릿 레포를 clone·조회·링크하지 않으며**, 생성 문서에도 그 링크를 남기지 않는다.

## 단계 요약

1. **사전 점검(쓰기 없음)**: 빈 디렉터리/기존 파일 확인. 이미 있는 파일은 `건너뜀`. `CLAUDE.md`에 `ai-workflow:` 마커가 있으면 이미 초기화된 프로젝트이므로 인터뷰를 반복하지 않고 빠진 파일만 제안한다. 마커 없는 기존 `CLAUDE.md`는 건드리지 않는다.
2. **인터뷰**(첫 질문 전에 "8문항 설정 인터뷰이며 아직 아무것도 쓰지 않았고 미리보기 승인 후에만 기록한다"는 안내 문구를 먼저 출력, 질문마다 "질문 n/8" 번호, 첫 메시지부터 사용자 언어 사용, 내부 단계 나레이션 금지; 한 번에 하나, 추천 답 포함): **문서 언어(질문 1: 생성 문서 `CLAUDE.md`·`docs/`·`issue-start`의 언어. English / 한국어 / 기타(직접 입력), 지금까지 쓴 언어를 추천. 코드·명령어·파일명·스킬 이름은 그대로. 인터뷰 자체는 사용자 언어로 계속하고 마커에 `lang=<en|ko|코드>`로 기록)** → 목적/범위 → 기술 스택(프론트/백/풀스택. 질문할 때 **이 워크플로우는 프론트엔드에 최적화되어 있고** 디렉터리 구조·도구 추천·`feature-strategy`가 프론트엔드 중심이며, 백엔드·풀스택도 동작하지만 기본값이 더 일반적이라고 먼저 밝힌다) → 명령어와 품질 도구(포매터·린터·테스트 러너. FE는 Biome, Vitest + Testing Library 추천, BE는 스택 표준 조합. 선택한 도구 이름을 "설치 예정"으로 기록하고 설치는 setup이 승인 후 한다) → 디렉터리 구조 → Out of scope → 큰 작업 워크플로우(**기술 스택을 확인한 뒤** 질문. FE/풀스택은 `feature-strategy` 기본 추천(**프론트엔드 전용 스택에는 "없음"을 제시하지 않고**, 요청해도 프론트엔드는 큰 작업 경로를 유지한다고 안내하며 `feature-strategy`로 정한다. `speckit`/직접 입력은 가능), 백엔드 전용은 `feature-strategy`가 프론트엔드 중심이라고 안내하며 `speckit` / 직접 입력 / 없음을 권하되 그래도 고르면 따른다. 직접 입력은 스킬 이름을 추가로 묻는다. 선택지마다 `presets.md`의 "One-line descriptions" 한 줄 설명을 함께 보여 주고, 특히 추천하는 `feature-strategy`는 "큰 흐름 먼저, 상세는 점진적으로 — 스토리 요구사항 → 하위 작업 로드맵 → 커밋 전마다 사람이 확인하며 하위 작업 하나씩 진행"하는 스킬이라고 먼저 설명한다) → 이슈 트래커(GitHub 이슈 추천 / 없음 — 이슈·라벨·`gh` 없이 로컬 문서만, `feature-strategy`는 피처 문서가 단일 소스이고 하위 작업은 `01`, `02` 번호 / 기타 — 이름만 묻고 "해당 트래커의 도구를 쓴다"로 위임, 특정 도구 명령은 쓰지 않음. 선택하지 않은 트래커의 흔적은 어떤 생성 파일에도 남기지 않는다).
3. **미리보기와 승인**: 파일별 `생성`/`건너뜀`과 치환될 값(목적, 스택, 전략 스킬 이름, 트래커), `.gitignore`에 추가될 줄을 보여 주고 승인받는다. 거절하면 아무것도 쓰지 않는다. 승인 후 `CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/TROUBLE_SHOOTING.md`, `docs/history/.gitkeep`, `.claude/skills/issue-start/SKILL.md`를 쓰고 `.gitignore`에 빠진 줄만 추가한다.
4. **요약과 다음 단계 안내**: 만든 것과 건너뛴 것을 요약하고 `/ai-workflow-setup`(플러그인 설치 시 `/dopeboy0608-skills:ai-workflow-setup`) 실행을 안내한다. 다른 스킬을 직접 실행하지 않는다.

## 규칙

- 선택한 전략 스킬 이름은 `CLAUDE.md`와 `issue-start`에 각각 한 곳에만 치환한다. 전략별 위치·규칙은 **선택한 전략 조각만** 읽어 삽입한 블록에만 두며, 선택하지 않은 전략의 이름·경로·설치 안내는 어떤 생성 파일에도 남기지 않는다. `none`이면 큰 작업 경로를 제거하고 가벼운 경로만 있는 `issue-start`를 만든다(`strategies/none.md`).
- 요약에 선택한 전략의 요구사항(예: "`speckit`이 설치돼 있어야 큰 작업 경로가 동작한다")을 명시한다. 전략 도구 설치는 `ai-workflow-setup`이 승인 후에 한다.
- `CLAUDE.md` 제목 아래 첫 줄에 `<!-- ai-workflow: version=1.4.6 strategy=<feature-strategy|speckit|custom:<스킬명>|none> tracker=<github|none|custom:<이름>> stack=… lang=<en|ko|코드> -->` 마커를 남긴다(어느 버전의 스킬로 만들었는지 구분, setup이 선택값을 읽는 용도).
- 생성 문서는 질문 1에서 고른 문서 언어로 쓴다(채팅 언어와 다를 수 있다). 한국어 고정 섹션 제목은 `SKILL.md`의 언어 대응표를 따른다.
- `docs/spec/`과 "스펙 선작성" 규칙은 만들지 않는다.
- 스캐폴딩 CLI 실행, 설치, 커밋, push, PR은 하지 않는다.
