# 02. feature-strategy 스킬 본문 > 하위티켓 생성 승인 흐름

## 목표
하위티켓을 자동으로 만들지 않고, 로컬 md 작성 뒤 사용자에게 묻고 승인 후에만 만들도록 스킬 본문을 고친다.

## 관련 FR

## 선행
01

## 범위 (In)
- Phase B step 6: 로컬 md 먼저 작성 → "하위티켓을 만들까요?" 질문, 기본값은 만들지 않음, 매번 묻는다
- 승인 시에만 트래커에 생성 (GitHub는 sub-issue 연결도 승인 후 실행)
- 라벨 생성은 명령만 출력하고 사용자가 직접 실행
- Operational notes와 Core principles에서 자동 생성으로 읽히는 문구 정리
- 이슈 생성 시 키 치환 규칙(Commit 줄)은 이슈를 만든 경우에만 적용
- (01에서 이월) Phase B 6단계의 "then write the feature doc: …" 문장은 01에서 추가한 "로컬 문서 먼저" 항목과 중복이므로 정리
- (01에서 이월) 6단계 "Create the sub-tasks under the story…"를 승인 후 생성으로 바꾼다 (01 이후 이 줄이 자동 생성으로 읽힘)

## 확인 시나리오
- [ ] 로컬 md 작성이 끝나기 전에는 이슈 생성 질문이 나오지 않는다
- [ ] 답이 없거나 거절이면 이슈를 만들지 않는다
- [ ] 승인 시에만 생성하고, 중복 확인 절차가 남아 있다
- [ ] 라벨 생성이 자동으로 읽히는 문구가 없다
- [ ] 이슈를 만들지 않아도 Phase C가 로컬 번호만으로 진행된다
